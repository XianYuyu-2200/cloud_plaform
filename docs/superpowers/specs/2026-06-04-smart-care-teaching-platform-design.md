# 智慧康养教学云平台设计

日期：2026-06-04

## 目标

建设一个可运行、可演示、可继续开发的智慧康养教学云平台。第一版采用“全栈演示平台”方案：前端具备接近参考图的深蓝科技大屏视觉，后端提供真实 API 边界，数据层使用本地种子数据或 SQLite，代码结构按正式云平台预留扩展口。

平台第一屏是教师课堂实训工作台，不做营销首页。教师可以快速检索案例、组织跌倒应急处置仿真实训、筛选测评方法和训练动作资源、查看学情分析，并基于评价体系形成课堂反馈。

## 非目标

- 第一版不导入完整 1000 个真实案例，但字段和导入接口预留。
- 第一版不实现正式登录、权限、多租户和云部署，但目录结构允许后续接入。
- 第一版不上传或托管真实教学视频，使用可替换的视频/图片资源 URL 或示例资源。
- 第一版不做复杂 3D 仿真，跌倒场景以交互式步骤仿真、任务选择和评分为主。

## 技术架构

采用单仓全栈结构：

- `apps/web`：React + Vite + TypeScript 前端。负责数字工区界面、模块导航、标签筛选、实训流程、图表和资源预览。
- `apps/api`：Node.js API 服务，优先使用 Express 或 Fastify。提供案例、资源、仿真、学情、评价和导入预留接口。
- `packages/shared`：共享类型、枚举、案例字段、资源字段、评分模型和 API DTO。
- `data`：本地种子数据、导入样例和可选 SQLite 数据库文件。

后续可将 `apps/api` 的数据层替换为 PostgreSQL 或 MySQL，将资源 URL 替换为对象存储地址，将课堂数据接入正式用户和班级权限体系。

## 视觉设计

整体风格参考用户提供的数字工区截图：

- 深蓝背景、青蓝荧光描边、半透明面板、科技感标题栏。
- 桌面大屏优先，兼容平板横屏。
- 首屏为总览工作台：左侧案例与资源，中间应急实训，右侧学情分析与评价体系。
- 使用高密度信息布局，避免营销型大标题和卡片堆叠。
- 关键控件采用标签、分段按钮、图表、评分条和步骤列表。

## 功能模块

### 案例库分类检索

案例按三大模块组织：

- 健康
- 亚健康
- 慢性病

每条案例包含性别、年龄段、身体状况、疾病种类、风险标签、课堂适用场景和摘要。教师可多标签筛选，快速获得候选案例，并将案例加入课堂任务。

### 应急处置场景仿真实训

第一版场景为“老年人跌倒应急处置”。任务步骤包括：

1. 判断环境危险源
2. 判断意识状态
3. 询问疼痛和禁忌
4. 检查生命体征
5. 呼救与转运决策
6. 记录处置并复盘

每一步提供交互选项、提示、得分和扣分原因。完成后生成总分、分项评分和实训报告。

### 测评方法库和动作库

资源按种类、部位、难度、适用人群和器械分类。教师可筛选方法或动作，点击后查看图片/视频区域、操作要点、注意事项和课堂引用按钮。第一版使用种子资源，后续可导入真实微课视频。

### 学情分析

学情分析聚合学生的案例学习、实训步骤、资源学习和评价结果，形成：

- 班级总览指标
- 学生个人画像
- 综合能力得分
- 分项能力图表
- 积分排行和近期表现

第一版使用模拟班级和学生数据，接口按真实课堂记录预留。

### 评价体系

评价体系包含安全、质量、时效、规范、沟通等维度。每个实训步骤和课堂任务可映射到评价维度，最终生成总分、分项得分和反馈建议。第一版提供固定规则，后续可扩展为可配置规则管理。

## 数据模型

核心实体：

- `CaseRecord`：案例，含分类、性别、年龄段、身体状况、疾病种类和标签。
- `LearningResource`：测评方法或训练动作资源，含类型、部位、难度、媒体 URL、要点和注意事项。
- `SimulationScenario`：仿真场景，第一版为跌倒应急处置。
- `SimulationStep`：场景步骤，含选项、评分规则和提示。
- `SimulationSession`：一次实训会话，记录学生选择、步骤状态和得分。
- `StudentProfile`：学生画像，含积分、能力指标和近期记录。
- `EvaluationRule`：评分规则，含维度、权重和扣分条件。

## API 设计

第一版 REST API：

- `GET /api/overview`：工作台总览。
- `GET /api/cases`：案例筛选列表。
- `GET /api/cases/:id`：案例详情。
- `GET /api/resources`：测评方法和动作库筛选列表。
- `GET /api/resources/:id`：资源详情。
- `GET /api/scenarios/fall`：跌倒仿真场景配置。
- `POST /api/simulations`：创建仿真会话。
- `POST /api/simulations/:id/steps/:stepId`：提交步骤选择并返回评分。
- `GET /api/simulations/:id/report`：获取实训报告。
- `GET /api/analytics/classroom`：班级学情分析。
- `GET /api/evaluations/rules`：评价规则。
- `POST /api/import/cases/preview`：案例导入预览预留接口。

## 数据流

工作台加载时先请求概览数据、班级学情摘要和最近实训记录。案例库和资源库通过统一标签筛选接口返回列表和统计。仿真实训采用会话式数据流：前端创建会话，逐步提交操作，后端返回步骤得分、提示和下一步状态，最终生成报告。学情分析从训练记录、资源学习记录和评分结果中聚合。

## 错误和空状态

- 无筛选结果：在当前面板展示空状态和清空筛选操作。
- 资源媒体未配置：展示待接入媒体区、操作要点和“待导入视频”提示。
- 实训未完成：报告区展示当前进度和继续训练入口。
- API 错误：模块面板内展示可恢复提示，保留页面整体结构。
- 导入字段不匹配：预览接口返回缺失字段、异常行和可修复建议。

## 测试策略

- 单元测试：标签筛选、评分汇总、评价维度计算。
- API 测试：核心接口返回结构和错误分支。
- 前端测试：关键页面渲染、筛选交互、实训步骤流转。
- 浏览器验收：桌面 1280x720 和平板横屏视口检查布局、文字不重叠、核心模块可见。

## 第一版验收标准

- 本地一条命令可启动前端和 API。
- 首屏呈现参考图风格的数字工区工作台。
- 五个业务模块均有可点击、可筛选或可流转的演示交互。
- 案例、资源、仿真、学情和评价数据通过 API 提供。
- 代码结构清晰，后续可接真实案例导入、正式数据库、权限和部署。
